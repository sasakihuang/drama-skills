# 图文动效路线：K 线、图表、文字讲解类

原片画面里没有人、没有实拍场景，主体是 K 线、图表、数据、文字、图标在动（财经讲解、知识科普、
数据盘点、清单类），就走这条路线，不走 AI 出图、出视频那条链。那条链又贵，又画不准图表。

动画用 **HyperFrames** 做：用网页写动画，在本机渲成 MP4，专门给 AI 助手用的。它是 HeyGen 开源的
`heygen-com/hyperframes`，Apache-2.0 许可证，可以商用，也不按次收费。只用它的本机渲染，不需要 HeyGen
账号，也不连 HeyGen 的服务：HeyGen 在国内直连不通。

## 为什么有这条路线：一次翻车

第一次实测时，这类片子交给了出片流程，结果手边没有做动画的工具。助手只好用画静态图的库
（matplotlib、mplfinance、PIL）一张张画，再拼成视频，做出来就是一套幻灯片。对比原片量出来的问题：

| 问题 | 翻车那条 | 原片 |
|---|---|---|
| 画面不动的时间 | 99.6%，最长 12.9 秒没变化，开头 3 秒全静止 | 52%，最长 2.4 秒 |
| 版式 | 十段全套一个「标题栏、左图框、右文字框、底字幕条」的后台报表模板 | 满屏大 K 线，大字标注直接打在线旁边 |
| 配音 | 新闻播报腔，十段之间空 1 到 3 秒，还被放慢到 0.9 倍凑时长，没有配乐 | 声音从头到尾不断，底下垫着配乐 |
| 文案 | 句句打折扣（「还不能下结论」「不是保证」），像念免责声明 | 自信的干货口气 |

下面每一条规矩都是冲着这几个毛病定的。

## 不准做的

- 不用 matplotlib、mplfinance、PIL/Pillow、OpenCV 这类画静态图的库逐帧拼动画。图表在 HyperFrames
  的网页里用代码画，用时间线做动画。
- 不把每段都做成同一个版式。
- 不后期放慢配音。
- 段与段之间不留 0.6 秒以上的空白。
- 不默认用播报腔音色。

## 0. 装一次（免费）

- 要 Node.js 22 或更新的版本，还要 ffmpeg。Node 版本不够就先帮创作者装新版。
- 把 [K 线起步模板](../assets/kline-starter/index.html) 连同它的 `package.json` 复制到项目的
  `制作/动画/`，在那个目录里运行一次 `npm install`（大约 100 MB）。HyperFrames、动画库 GSAP、
  两款字体和一套音效都装进这个目录，版本是钉死的，渲染时不连外网。下载太慢就让 npm 走国内镜像。
- HyperFrames 会发匿名使用统计。跑任何 `hyperframes` 命令之前先关掉：PowerShell 里执行
  `$env:HYPERFRAMES_NO_TELEMETRY="1"`，macOS 和 Linux 执行 `export HYPERFRAMES_NO_TELEMETRY=1`。
- 下面所有 `npx hyperframes …` 都在 `制作/动画/` 里运行，用的是刚装的那一份。第一次先运行
  `npx hyperframes browser ensure`：它会下载一个专门用来渲染的 Chrome，然后用
  `npx hyperframes doctor` 看环境齐不齐。
- 动手搭画面前，先读 HyperFrames 自己的说明：`node_modules/hyperframes/dist/skills/hyperframes/SKILL.md`，
  再在终端里看 `npx hyperframes docs compositions`、`docs data-attributes`、`docs gsap`。出错时看
  `docs troubleshooting`。不用另外装它的技能。
- 不用 HyperFrames 的 `reverse-any-video`：它是付费功能，而且逐帧照抄原片，违反本技能「内容全换」的规矩。

## 1. 顺序：先定稿，再配音，画面跟着声音走

旁白定稿 → 试听选声 → 全片配音 → 量出每段配音的长度 → 按配音长度排动画 → 配乐和音效 → 渲染
→ 对照原片检查。

原片的切点只用来定**段落顺序和各段的比例**，不要把配音硬塞进原片的切点：配音短了就放慢、
就留空白，正是翻车的根子。新片每段的长度等于这段配音的长度，再加 0.3 秒左右换气。

## 2. 写旁白稿

建项目、写节奏档案照 [交接](handoff.md) 的第 1、2 步做，`form` 填 `motion_comic`（套件里最接近的一档）。
旁白稿仍然由 `$short-drama-write` 写进《剧本.md》，交接时把下面几条一起交过去：

- **口气照原片。** 原片是自信的「战法、干货」口气，新稿也这么说：短句、口语、敢下判断。原片的句子
  一句都不能用，但口气要学。
- **提醒只说一次。** 财经类在片尾说一句「示意图，不构成投资建议」就够了，正文不要句句加
  「不一定」「不是保证」「还要再看」。唯一的红线是：不许诺收益，不喊具体股票的买卖。
- **字数按原片的语速算。** 新稿总字数大约等于「原片每秒字数 × 原片有人声的秒数」。拆解时用
  `media_profile.py` 和台词识别量出语速；没有识别结果，就按画面字幕的字数估。知识类短视频大约
  每秒 4.5 到 5.5 个字。稿子短了就补内容，比如多讲一个例子、多下一句判断，不靠放慢配音来凑。
- 每段的第一句就是这段的看点。

## 3. 试听选声（第二个停顿点的前一半）

原片的声音你听不见。所以先让创作者用耳朵挑，挑定了再配全片：

1. 从创作者账号的音色里挑三四个候选。原片是男声还是女声、大概多大年纪、什么劲头，拆解时问过
   创作者就照他说的挑；没问过，就男女各两个。知识讲解类可以先从这几个里挑（以账号实际的音色列表为准）：

   | 音色编号 | 名字 | 适合 |
   |---|---|---|
   | `male-qn-jingying` | 精英青年 | 干脆利落的干货口气 |
   | `Chinese (Mandarin)_Sincere_Adult` | 真诚青年 | 亲切、像朋友在讲 |
   | `Chinese (Mandarin)_Reliable_Executive` | 沉稳高管 | 稳、有分量 |
   | `Chinese (Mandarin)_Unrestrained_Young_Man` | 不羁青年 | 带点情绪、节奏快 |
   | `Chinese (Mandarin)_Warm_Bestie` | 温暖闺蜜 | 女声，清脆友好 |
   | `female-yujie` | 御姐 | 女声，干练 |
   | `Chinese (Mandarin)_Wise_Women` | 阅历姐姐 | 女声，成熟有阅历 |
   | `female-chengshu` | 成熟女性 | 女声，稳重 |

   `Chinese (Mandarin)_News_Anchor`（新闻女声）和 `Chinese (Mandarin)_Male_Announcer`（播报男声）是
   播音腔，听起来像机器人念稿。除非原片本来就是新闻播报，否则不放进候选。
2. 每个候选只配钩子那一句（十几个字，每条几分钱），`speed` 先给 1.1。走 `$short-drama-produce`
   的报价和确认，不能绕开。
3. 把几条试听文件列给创作者，用选项卡问他：选哪一个，都不行就换一批，或者整体调快调慢。
4. 他选定以后，`$short-drama-assets` 把音色编号和 `speed` 写进《视觉设定.md》的声音方向。

## 4. 配乐（第二个停顿点的后一半）

拆解时 `media_profile.py` 给出原片 `continuous_bed: true`，说明原片底下垫着配乐，新片也要垫。

配乐默认从本技能附带的 [Mixkit 精选清单](music-catalog.json) 里取：32 首，分 8 种情绪。每首的许可都核过
（Mixkit Stock Music Free License：可商用、可发社交平台视频、不用署名），国内直连能下，不用登录，
不用看画面挑。

1. 看清单：`python3 <本技能目录>/scripts/fetch_music.py list`，加 `--mood 科技财经` 只看一种情绪。
   按原片配乐的情绪挑最接近的一种；讲解类一般是「科技财经」或「舒缓安静」。
2. 挑两首候选，先下载下来给创作者试听（只下载，不做垫底）：

```bash
python3 <本技能目录>/scripts/fetch_music.py fetch <编号> --out <项目>/制作/配乐
```

3. 和音色试听放在同一次停顿里，把两首的文件和歌名列给他：选一首，或者说「都不行，换个感觉」，
   再从另一种情绪里挑。
4. 创作者自己给了有使用权的音乐文件，就用他的，跳过清单。
5. 下载失败（打不开 assets.mixkit.co）：换清单里另一首再试；都不行，就只加音效，段间换气压到 0.3 秒以内，
   并告诉创作者成片会比原片「空」一些。

不准：用清单以外的 Mixkit 歌（许可没核过）、提取原片的音乐、从网上随便下歌。试听时听到配乐里有人声唱词，
就换一首，免得和旁白打架。

## 5. 全片配音（第二个停顿点之后）

- 一段一条配音任务，这一段整段连着读，不要拆成一句一条。音色和 `speed` 照创作者选定的写。
- **快慢只用生成参数 `speed` 调，不准后期放慢**，也就是 ffmpeg 的 `atempo` 不能小于 1。
  后期顶多在 1.00 到 1.05 之间微调。
- 配完用 ffprobe 量每段的时长，写进 `制作/时间表.json`。每段记：段号、开始时间、配音时长、
  这段总时长（配音时长加 0.3 秒左右）。后面排动画、切字幕、放音效都照这张表。
- 字幕一句一条。每句的时间先按字数比例在这段配音里分配；本机装了台词识别，就用
  `transcribe.py` 识别配音、对到句，这样更准。

## 6. 搭画面：HyperFrames

第 0 步复制过来的 `index.html` 就是起步模板，模板里已经做好了这些：K 线一根根长出来，镜头推近关键那根，其余变暗，加发光圈和大字标注，
画支撑线，标题砸下来带闪光和火星，字幕淡入淡出。在它上面改，不要从零写。

一个画面原片做的是 K 线以外的东西（文字清单、数据对比、流程图），就照同样的思路写：
整屏一个主体，每一两秒有一个动作。

搭法：

- 全片一个 `index.html`，根节点宽高取原片画幅（横屏 1920×1080，竖屏 1080×1920）。每段从
  `时间表.json` 里取开始时间和时长。段多、文件太长时，照 `docs compositions` 的做法拆成子合成。
- 图表数据放在页面里的数组中，按讲解要的形状编。全部标「示意」，不用真实股票的名字和代码。
- 动画只动这些属性：位置、缩放、旋转、透明度、颜色。不用随机数；真要随机，用固定种子，
  模板里有写法。

画面规矩：

1. **满屏。** 主图占画面六成以上，不套框、不做后台报表那种版式。
2. **每一两秒有一个动作。** 最长不动的时间不超过原片最长不动的时间加 1 秒，第 8 步会量。可以用的动作：
   - K 线「长」出来：实体从开盘价往收盘价伸，影线随后拉出，带缓动；
   - 镜头推近：讲到哪根线就推到哪根，讲完拉回全图；
   - 高亮：关键那根外面套发光圈、做脉冲，其余的变暗；
   - 划线：支撑线、压力线从左往右画出来，区间用半透明的带子扫过去；
   - 量柱从底下弹起，放量的那根变色、跳一下；
   - 大字标注：1080p 画面下字号不小于 64px，配箭头指着那根线，弹出时配「pop」音效；
   - 换段转场：整张图滑走、缩放切换、光扫过去，配「whoosh」音效。
3. **开头 3 秒必须有大动作。** 首帧就有字，标题砸出来，配冲击音效。原片标题怎么出场就怎么学，
   字换成新标题。
4. **风格照原片的系统换。** 底色、涨跌颜色、重点色、字体的类别（毛笔、手写、粗黑体）都学原片；
   字体只用可商用的开源字体。模板里的思源黑体和马善政毛笔体都是 OFL 许可证。
5. **字幕放在底部。** 1080p 下字号不小于 50px，带描边，不和标注撞在一起。
6. **片尾**：一句风险提示，再加「AI 配音」标识。

画面搭好后先跑检查：`npx hyperframes check`，要 0 个错误。再用
`npx hyperframes snapshot --at <每段中点的秒数，用逗号隔开>` 每段截一张，自己逐张看，
看有没有字出画、盖住、挤在左上角。

## 7. 混音

1. 配音全部配完、拼成一条 `旁白.wav` 以后，用选定的那首做配乐垫底：

```bash
python3 <本技能目录>/scripts/fetch_music.py fetch <编号> --out <项目>/制作/配乐 --voice <项目>/制作/旁白.wav --length <全片秒数>
```

   它会生成 `配乐垫底.wav`：从歌的第一个音开始，切掉结尾的淡出尾巴；成片比歌长就用 1.5 秒交叉淡化
   循环接上；剪到全片长度；开头淡入 0.5 秒，结尾淡出 1.5 秒。音量按实测设在旁白下面 13 LU，
   混音时**不要再调它的音量**。同目录的 `配乐来源.md` 写进交付记录。
2. 音效用 HyperFrames 自带的音效库：`node_modules/hyperframes/dist/skills/media-use/audio/assets/sfx/`，
   Pixabay 许可，可以商用。几个常用的：转场用 `whoosh`，标注弹出用 `pop` 或 `click`，重要结论用 `impact-bass-1`，
   开头用 `riser`。每段放两到四个，不要满屏响。
3. 三样混在一起，整片统一音量。文件名和时间按实际情况换（`adelay` 后面的数字是毫秒）：

```bash
ffmpeg -i 旁白.wav -i 配乐垫底.wav -i whoosh.mp3 -i pop.mp3 -filter_complex "[0:a]aformat=sample_rates=48000:channel_layouts=stereo[v];[2:a]aformat=sample_rates=48000:channel_layouts=stereo,adelay=4300|4300,volume=0.35[s1];[3:a]aformat=sample_rates=48000:channel_layouts=stereo,adelay=5400|5400,volume=0.35[s2];[v][1:a][s1][s2]amix=inputs=4:duration=longest:normalize=0,loudnorm=I=-13:TP=-1.5:LRA=9[out]" -map "[out]" -ar 48000 混音.wav
```

   没有配乐时，把 `配乐垫底.wav` 那一路去掉，`amix` 的路数跟着减。
4. 混好的 `混音.wav` 放进 `index.html`，作为根节点下的一个 `<audio>` 片段，从 0 秒开始、
   时长等于全片时长。写法见 `docs data-attributes`。

## 8. 渲染和检查

1. 先渲一版快的：`npx hyperframes render --quality draft --output 成片-草稿.mp4`。
2. 拿它和原片比：

```bash
python3 <本技能目录>/scripts/media_profile.py 成片-草稿.mp4 --compare <参考片目录>/source.profile.json
```

   不通过的项先自己修，再重渲。修不了的，在复刻方案的成片对照里写明原因。
3. 把草稿版和检查结果交给创作者，这是第三个停顿点。他满意了，再渲正式版：
   `npx hyperframes render --quality high --output <成片名>.mp4`。
   正式版也要再跑一遍上面的对比。
