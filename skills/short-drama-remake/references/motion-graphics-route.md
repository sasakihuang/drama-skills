# 图文动效路线：K 线、图表、文字讲解类

原片画面里没有人、没有实拍场景，主体是 K 线、图表、数据、文字、图标在动（财经讲解、知识科普、
数据盘点、清单类），就走这条路线，不走 AI 出图、出视频那条链。那条链又贵，又画不准图表。

动画用 **HyperFrames** 做：用网页写动画，在本机渲成 MP4，专门给 AI 助手用的。它是 HeyGen 开源的
`heygen-com/hyperframes`，Apache-2.0 许可证，可以商用，也不按次收费。只用它的本机渲染，不需要 HeyGen
账号，也不连 HeyGen 的服务：HeyGen 在国内直连不通。

## 为什么有这条路线：量出来的教训

头几次实测，这类片子的毛病都能量出来：

| 毛病 | 当时的样子 | 原片 |
|---|---|---|
| 画面像幻灯片 | 用画静态图的库一张张拼：99.6% 的时间不动，最长 12.9 秒没变化 | 52%，最长 2.4 秒 |
| 版式一个样 | 十段全套「标题栏、左图框、右文字框、底字幕条」 | 满屏大 K 线，大字标注直接打在线旁边 |
| 声音冷场 | 播报腔，段间空 1 到 3 秒，还被放慢去凑时长，没有配乐 | 声音从头到尾不断，底下垫着配乐 |
| 片子拖长 | 字数按原片语速算，选的音色却慢：47 秒的片做成 61 秒，4 分 37 秒的做成 5 分 26 秒 | 照原片的时长 |
| 文案走样 | 句句打折扣，像念免责声明；下判断的词原片 15 处，新稿只有 3 处 | 自信的干货口气 |

教训有两条。第一条：量得出来的才管得住。画面动不动、有没有冷场、音量，有了检查以后每条片都达标；只写在文字里的
口气和时长，每条都走样。所以这条路线里，能交给脚本量的都交给脚本。第二条：拼旁白、对字幕、混音这些机械活，
每次现写一遍又慢又容易错，用技能自带的脚本，不要自己重写。

## 不准做的

- 不用 matplotlib、mplfinance、PIL/Pillow、OpenCV 这类画静态图的库逐帧拼动画。
- 不把每段都做成同一个版式。
- 不后期放慢配音。
- 段与段之间不留 0.6 秒以上的空白。
- 不默认用播报腔音色。
- 不自己写拼旁白、对字幕时间、混音的脚本：用 `voice_track.py` 和 `mix_audio.py`。
- 不自己算每样东西出现的秒数：`film.json` 里的 `at` 直接抄旁白里的字，时间由 `animation.py build` 去找。
- 不直接运行 `npx hyperframes …`：都经过 `animation.py`。它关掉了使用统计，也不运行会弹窗口、会把项目传到网上的命令。

## 0. 装一次（免费）

```bash
python3 <本技能目录>/scripts/doctor.py
python3 <本技能目录>/scripts/animation.py setup <项目>/制作/动画
```

- `<项目>` 就是下载参考片时定下的那个项目文件夹（SKILL.md 第 1 步）。`setup` 只是往里放动画模板，
  排在建项目前面还是后面都行。
- `doctor.py` 一次说清这台电脑缺什么：ffmpeg、Node.js 22、密钥文件、识别台词的程序、动画工具。缺的一次问清创作者。
- `setup` 第一次运行时给全电脑装一份 HyperFrames（约 200 MB，在用户目录的 `.drama-skills/hyperframes` 里，版本钉死，
  先走国内镜像），以后每条片子共用，不在项目里再装。然后把画面模板放进动画目录：`index.html`、
  `lib/`（模板脚本、动画库、五个字体文件，约 6 MB）和一份示例 `film.json`。
- 画幅取原片的：横屏 1920×1080；原片是竖屏，**第一次** `setup` 就加 `--portrait`，就是 1080×1920。
  已经放了横屏的模板才想起来要竖屏，再跑一次并加上 `--portrait --force`（`film.json` 不会动）。
- **不弹网页，不开它的 App。** 自己看画面用 `animation.py snapshot`，给创作者看用渲好的 MP4。`animation.py`
  不运行 `preview`、`play`、`present`、`open`（会弹浏览器或桌面 App）、`publish`（把项目传到 HeyGen 网上）和
  `skills`（把 HyperFrames 的技能装进你自己，以后的对话也会被它带着开编辑页）。只有创作者明确说要在网页里
  自己动手改，才运行 `animation.py tool <动画目录> --creator-asked-for-editor -- preview --background`，
  把打印出来的链接发给他自己点；他改完，运行 `animation.py tool <动画目录> -- preview --stop` 关掉。
- 创作者说浏览器里老弹出 HyperFrames 的编辑页：运行上面那条 `preview --stop`，再请他关掉那个网页。要是你的技能目录
  里有 `hyperframes` 开头的文件夹，说明以前装过它的技能，告诉创作者，由他决定删不删。
- 不用 HyperFrames 的 `reverse-any-video`：它是付费功能，而且逐帧照抄原片，违反本技能「内容全换」的规矩。

## 1. 顺序：先定稿，再配音，画面跟着声音走

旁白稿 → 写稿检查 → 试听选声 → 按选定的音色估时长、调字数 → 全片配音 → 拼旁白、出时间表
→ 照时间表排画面 → 配乐和音效 → 渲染 → 对照原片检查。

原片的切点只用来定**段落顺序和各段的比例**，不要把配音硬塞进原片的切点：配音短了就放慢、
就留空白，正是翻车的根子。新片每段的长度等于这段配音的长度，再加 0.3 秒左右换气。

## 2. 写旁白稿

建项目照 [交接](handoff.md) 的第 1 步做。**这条路线不写节奏档案，也不定语速**：字数和时长由 `script_check.py`
按选定的音色管。建完项目，`$short-drama` 的状态里会挂一条「设了目标时长却没有语速」的提示，不用理，也不要拿去问创作者。

旁白稿仍然由 `$short-drama-write` 写进《剧本.md》：场景标题里的地点写画面是什么（例如「内 · 黑底图表画面 · 不限」），
每句旁白写成 `[VO] 旁白：……`。交接时把 [口播稿写法](voiceover-writing.md) 的要点一起交过去，最要紧的是这几条：

- **口气照原片。** 原片是自信的「战法、干货」口气，新稿也这么说：短句、口语、敢下判断。原片的句子
  一句都不能用，但口气要学。观点默认照原片讲，要改先问创作者。
- **提醒只说一次。** 财经类在片尾说一句「示意图，不构成投资建议」就够了，正文不要句句加
  「不一定」「不是保证」「还要再看」。唯一的红线是：不许诺收益，不喊具体股票的买卖。
- **字数按音色算，不按原片的语速算。** 同一份稿，不同音色念出来能差两三成。写之前先跑
  `script_check.py budget <参考片目录> --cuts <各段起点>` 拿每段的字数；这时还没选音色，它按原片语速给，
  只够写初稿用。它给的是一个范围，**上限是正好念满这一段的字数**：句子短、停顿多的稿子念得更久，写在范围中间，
  不要顶着上限写。稿子短了就补内容，比如多讲一个例子、多下一句判断，不靠放慢配音来凑。
- 每段的第一句就是这段的看点。

初稿写完先查一遍，口气和照搬不通过就改稿，过了再去试听：

```bash
python3 <本技能目录>/scripts/script_check.py check <项目>/剧集/EP001/剧本.md --reference <参考片目录> --voice-over-only
```

`--voice-over-only` 让它只看旁白行，不会把「某某：……」样子的画面说明当成台词数进去。

## 3. 试听选声（第二个停顿点的前一半）

原片的声音你听不见。所以先让创作者用耳朵挑，挑定了再配全片：

0. **先看「我的音色」**：运行 `python3 <本技能目录>/scripts/my_voices.py list`。创作者以前存过满意的音色，就先问他：
   直接用其中哪一个（列出名字和备注，附上存着的试听录音让他再听一遍），还是重新试听。他选了存好的，就跳过
   下面的第 1 到 3 步，直接到第 4 步。
1. 从 [中文音色清单](voice-catalog.json) 里挑四个候选。清单里有 58 个音色，标了男女、年纪、劲头和适用范围：
   - 默认只从 `fit` 为「讲解」的 36 个里挑。「角色」「播音」「童声卡通」这几类，原片本来就是那种风格或创作者点名
     才用。播音腔（新闻女声、播报男声）听起来像机器人念稿。
   - 按拆解报告里原片的男女、年纪和口气挑最接近的；没问过原片是男是女，就男女各两个。四个之间劲头要拉开，
     别挑四个差不多的。不要每次都从清单最前面拿。
   - 创作者描述了想要的感觉（比如「更沉稳、像财经博主」），就按描述挑。
   - 这个项目里已经试听过的音色记在 `制作/试听/已试听.json`，「换一批」时不再重复推。
2. 每个候选只配钩子那一句（十几个字，每条几分钱），`speed` 先给 1.1。走 `$short-drama-produce`
   的报价和确认，不能绕开。
3. 把几条试听文件列给创作者，用选项卡问他：选哪一个；都不行就换一批；或者整体调快调慢。
4. 他选定以后，`$short-drama-assets` 把音色编号和 `speed` 写进《视觉设定.md》的声音方向。
5. 选定的是新试听出来的音色，就问他一句：「要不要存进我的音色，以后直接用？起个名字吧」。他同意就存：

```bash
python3 <本技能目录>/scripts/my_voices.py save --name <他起的名字> --voice-id <音色编号> --speed <语速> --sample <听中的那条试听文件> --project <项目名>
```

   用的是存好的音色，就记一笔用在了哪：`my_voices.py used --name <名字> --project <项目名>`。

## 4. 配乐（第二个停顿点的后一半）

拆解时 `media_profile.py` 给出原片 `continuous_bed: true`，说明原片底下垫着配乐，新片也要垫。

配乐默认从本技能附带的 [Mixkit 精选清单](music-catalog.json) 里取：32 首，分 8 种情绪。每首的许可都核过
（Mixkit Stock Music Free License：可商用、可发社交平台视频、不用署名），国内直连能下，不用登录，
不用看画面挑。

1. 看清单：`python3 <本技能目录>/scripts/fetch_music.py list`，加 `--mood 科技财经` 只看一种情绪。
   按原片配乐的情绪挑最接近的一种；讲解类一般是「科技财经」或「舒缓安静」。
2. 挑两首候选，先下载下来给创作者试听（只下载，不做垫底）：

```bash
python3 <本技能目录>/scripts/fetch_music.py fetch <编号> --out <项目>/制作/配乐
```

3. 和音色试听放在同一次停顿里，把两首的文件和歌名列给他：选一首，或者说「都不行，换个感觉」，
   再从另一种情绪里挑。
4. 创作者自己给了有使用权的音乐文件，就用他的，跳过清单。
5. 下载失败（打不开 assets.mixkit.co）：换清单里另一首再试；都不行，就只加音效，段间换气压到 0.3 秒以内，
   并告诉创作者成片会比原片「空」一些。

不准：用清单以外的 Mixkit 歌（许可没核过）、提取原片的音乐、从网上随便下歌。试听时听到配乐里有人声唱词，
就换一首，免得和旁白打架。

## 5. 全片配音（第二个停顿点之后）

- **报价之前，先按选定的音色估全片时长**（免费，几秒）：

  ```bash
  python3 <本技能目录>/scripts/script_check.py check <项目>/剧集/EP001/剧本.md --reference <参考片目录> --voice-over-only --voice-id <音色编号> --speed <语速> --audition <他听中的那条试听> --audition-text "<试听念的那一句>"
  ```

  「时长对得上」不通过，就照它给的数删稿或补内容（交回 `$short-drama-write`），改完再跑；它也可能提议
  把语速调到 1.0 到 1.25 之间的某个数，那要让创作者重听一句再定。它写「提示……偏长」时（比原片长半成到一成），
  默认照它说的字数删到贴上原片；不删就要在报价时明说成片会比原片长几秒。过了才报价，报价时告诉创作者
  预计全片多长、原片多长。用的是存好的「我的音色」、没有新试听时，不带后两个参数。
- 一段一条配音任务，这一段整段连着读，不要拆成一句一条。音色和 `speed` 照创作者选定的写。
- **快慢只用生成参数 `speed` 调，不准后期放慢**，也就是 ffmpeg 的 `atempo` 不能小于 1。
  后期顶多在 1.00 到 1.05 之间微调。
- 配完运行一次，把各段拼成一条旁白，并算出每句话的时间（免费，几秒）：

  ```bash
  python3 <本技能目录>/scripts/voice_track.py build --project <项目> --jobs <各段配音任务号，按片子里的顺序，逗号隔开> --out <项目>/制作 --reference <参考片目录>
  ```

  它写出 `制作/旁白.wav`、`制作/时间表.json`（每段从哪开始、多长，每句话的起止时间，切好的字幕）和 `制作/字幕.srt`。
  段首段尾的空白它会剪掉，段间留 0.3 秒；每句话的时间是从声音里量出来的，不是按字数估的。后面排画面、放音效
  都照这张表，不要自己另算。它顺手把这个音色的实测语速记下来，下一条片子用同一个音色时，估时会更准。
- 配完以后又改了某一段的稿子，它会点出是哪个任务号并停下：录音念的还是旧稿，字幕会对不上。把那一段重新配
  （要再走一次报价和确认），或者把稿子改回去，再运行。
- 它会说成片比原片长了还是短了。差出一成以上，把实际时长告诉创作者，由他定：接受，或者改稿重配其中几段。

## 6. 搭画面

画面不用从零写。你只写一份 `制作/动画/film.json`：全片分成几个画面，每个画面是哪一种、管哪一段旁白、
上面写什么字、每样东西在旁白说到哪几个字时出现。**动手前先读 [画面清单怎么写](film-json.md)**：每种画面的字段、
例子和常见毛病都在那里，不用去翻模板的源码。`setup` 放进去的那份 `film.json` 是示例，照着改。然后：

```bash
python3 <本技能目录>/scripts/animation.py build <项目>/制作/动画 --timetable <项目>/制作/时间表.json
python3 <本技能目录>/scripts/animation.py cues <项目>/制作/动画
python3 <本技能目录>/scripts/animation.py check <项目>/制作/动画
python3 <本技能目录>/scripts/animation.py snapshot <项目>/制作/动画
```

- `build` 把每个画面、每样东西的时间从时间表里算好，字幕也一并排上。它会直接指出：哪一段旁白没有画面管、
  哪个画面开头是空的、哪个 `at` 抄的字这个画面里没说过。
- `cues` 把全片列成对词清单：每样东西第几秒出现、那一刻旁白在说哪一句。**逐行读**，画面上的字和旁白说的不是
  一回事就改。这一步几秒钟、不出图，先做它，再截图。
- `check` 要 0 个错误。
- `snapshot` 每个画面开头截一张，每样东西出现后各截一张，汇总图在 `制作/动画/snapshots/`。自己逐张看：有没有字出画、
  盖住、挤在一起。要细看某几个时刻加 `--at 秒数,秒数`，那一批存在 `snapshots-at/`。

能用的画面（字段见那份说明）：

| `type` | 画面 |
|---|---|
| `title` | 大标题砸出来，带闪光和火星，字上过一道高光；第一帧就有字 |
| `kline` | K 线一根根长出来；讲到哪根，镜头推近、其余变暗，套光圈、打大字标注；能圈一根、框一段、框量柱，能划线、划区间；能接着上一张图往下讲 |
| `compare` | 两张小图并排（竖屏上下排），各划一条线、各盖一个结论章 |
| `points` | 编号卡片：先出空位，讲到哪条亮哪条 |
| `bars` | 柱状图：讲到哪根长哪根，可以点亮其中一根（竖屏是横条） |
| `number` | 一个大数字滚出来，下面跟说明 |
| `statement` | 大字一行一行蹦出来 |
| `end` | 片尾提示和「AI 配音」 |

规矩：

1. **讲到哪，指到哪。** 每样东西的 `at` 抄旁白里说到它的那几个字，不要自己估秒数。旁白在讲成交量，镜头就要在
   量柱上；旁白在讲「后面这一段」，就把那一段框出来。
2. **每句旁白都有东西可看。** 一个画面只挂一个标题、等后面的句子才出内容，就是空屏。旁白在铺垫，画面也要先有东西：
   图先长出来，卡片先出空位。
3. **一段话换一两次画面。** 一个画面撑不过十几秒；同一种画面不要连用三次。同一张图要讲好几句时，拆成两个画面，
   后一个接着前一个的图往下讲，不要让同一张图从头再长一遍。
4. **开头 3 秒必须有大动作。** 第一个画面用 `title`，原片标题怎么出场就怎么学，字换成新标题。
5. **风格照原片的系统换。** `palette` 改涨跌颜色和重点色；底色只用深色，原片是浅底也用深底（浅色 `build` 会拒绝）。
   字体只用可商用的开源字体，模板带的思源黑体和马善政毛笔体都是 OFL 许可证。
   原片本身是另一种画风（扁平插画、线条、等轴小城、玻璃卡片……），新片题材也适合这种画风，拆解时就定下照
   [风格库](styles.md) 里的那一种画：`film.json` 写 `style`，画面全部自己写，浅色底也行，做法见那份说明。
   两头有一头对不上（K 线图表、口播片，或者题材和画风不搭），就用这套模板，不硬套。
6. 图表数据都是示意：用现成的走势，或者自己编一组数据，不用真实股票的名字和代码。
7. **片尾**用 `end`：一句风险提示，再加「AI 配音」标识。

## 7. 混音

1. 用选定的那首做配乐垫底，`--length` 取 `build` 报的全长：

```bash
python3 <本技能目录>/scripts/fetch_music.py fetch <编号> --out <项目>/制作/配乐 --voice <项目>/制作/旁白.wav --length <全片秒数>
```

   它会生成 `配乐垫底.wav`：从歌的第一个音开始，切掉结尾的淡出尾巴；成片比歌长就用 1.5 秒交叉淡化
   循环接上；剪到全片长度；开头淡入 0.5 秒，结尾淡出 1.5 秒。音量按实测设在旁白下面 13 LU。
   同目录的 `配乐来源.md` 记着下载过的每一首和垫底用的是哪一首，写进交付记录。
2. 混音。音效点 `build` 已经写在 `制作/动画/音效.json` 里：换画面配 `whoosh`，标注弹出配 `pop`，标题砸下来配冲击声。
   它自己守着密度：一段旁白里平均四秒左右一个，先留有意思的（标题、标注落下、结论章、数字），再留换画面的，
   其余的不响。音效取自 HyperFrames 自带的音效库（Pixabay 许可，可以商用），目录是 `setup` 输出里的 `sfx_root`。
   这份清单每次 `build` 都会重写：想自己加减，另存一份（例如 `制作/音效-我的.json`）再改，混音时 `--sfx` 指向它。
   清单里每个音效的 `volume` 是**相对旁白的响度**：1 是和旁白一样响，0.5 是轻 6 分贝。旁白和每个音效文件的音量
   `mix_audio.py` 都会实测，所以换一个音色、换一个音效文件，这个数的意思不变。模板给的数都在 0.45 到 0.6 之间：
   没有哪个音效比人声响。创作者说音效太吵或者听不见，改这个数，不要去动整片音量。

```bash
python3 <本技能目录>/scripts/mix_audio.py --voice <项目>/制作/旁白.wav --bed <项目>/制作/配乐/配乐垫底.wav --sfx <项目>/制作/动画/音效.json --sfx-root <sfx_root> --length <全片秒数> --like <参考片目录>/source.profile.json --out <项目>/制作/混音.wav
```

   没有配乐时不给 `--bed`。原片没人说话、新片也不配音的，不给 `--voice`（`fetch_music.py` 那一步也不给）：配乐铺满全片，
   音效的 `volume` 就是相对配乐的响度。`--like` 让整片的音量贴着原片（限在 -14 到 -11 LUFS 之间：比原片轻一大截，放在一起就显得没劲）；
   不给就是 -13 LUFS。它会报出实测的音量和峰值。`--length` 照抄 `build` 报的全长，不要自己四舍五入：全长是按整帧算的
   （例如 40.233333 秒），声音和画面一样长，渲染器才不会把声音重新压一遍。
3. 把声音放进片子：再运行一次 `build`，后面加上 `--mix <项目>/制作/混音.wav`。
   之后只改了字或颜色、没动时间，直接再 `build` 就行，声音留着。动了画面的时间或音效点，`build` 会把声音取下并提醒：
   那就从第 2 步重新混音，再 `build --mix`。

## 8. 渲染和检查

成片放在 `<项目>/剧集/EP001/制作成果/成片/`，下面叫它 `<成片目录>`。

1. 先渲一版快的：

```bash
python3 <本技能目录>/scripts/animation.py render <项目>/制作/动画 --output <成片目录>/<片名>-草稿.mp4
```

   渲完它会量一遍成片的音量，和放进去的混音比。渲染器偶尔会把整条声音调小好几分贝（它自己压声音时出了一个尖峰，
   就按尖峰把全片压低），这时 `render` 会把混好的那条换回去，并打印一行「注意」；不用你处理，照常往下走。
   它要是说「混音的峰值太高」，那是混音不是用 `mix_audio.py` 做的：用它重混。

2. 拿它和原片比。先识别一遍成片的旁白（十几秒），不然「语速」那一项没法比：

```bash
python3 <本技能目录>/scripts/transcribe.py <成片目录>/<片名>-草稿.mp4
python3 <本技能目录>/scripts/media_profile.py <成片目录>/<片名>-草稿.mp4 --compare <参考片目录>/source.profile.json
```

   「不通过」的项先自己修，再重渲。修不了的，在复刻方案的成片对照里写明原因。「提示」的项不拦，但要告诉创作者
   （比如比原片轻了多少）。这条对照只量得出声音和画面，口气它不管：口气在写稿检查那一步已经把过关，稿子后来
   改过就再跑一次 `script_check.py check`。
3. 做两张封面（竖 1080×1920、横 1920×1080），做法见 [封面](cover.md)。这条路线给 `frames` 加
   `--animation <项目>/制作/动画`：封面的画面从动画重新截，不带字幕和画面小标题。
4. 把草稿版 MP4、两张封面和检查结果交给创作者，这是第三个停顿点。他满意了，再渲正式版：同一条命令加 `--final`，
   文件名换成正式版的。正式版也要再跑一遍上面的对比，再把 `封面.json` 的 `film` 换成正式版、跑一次 `cover.py make`。
5. 交付时照 SKILL.md 第 6 步的「交付成片时」做：写出成片所在文件夹的路径和链接，并直接打开文件夹、选中成片。
   草稿版也一样。
