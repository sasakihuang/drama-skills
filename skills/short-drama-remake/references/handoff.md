# 交接：把复刻方案交给出片流程

这份交接管**剧情和实拍类**。图文动效类（K 线、图表、文字讲解）只用这里的第 1 步建项目，
节奏档案和语速它都不写，后面照 [图文动效路线](motion-graphics-route.md) 做。

复刻方案定稿后，本技能不自己写剧本、不自己出图出视频。每份创作文档仍由它原来的技能负责，
本技能只把方案交过去，并在 `复刻方案.md` 的「交接记录」里一步写一行。

这条路上创作者要回答的不止三次。先把下面这张表讲给他听，免得他以为中间只停一回：

| 什么时候 | 问他什么 | 谁来问 |
|---|---|---|
| 方案写完 | 照推荐的走、换题材或尺度、还是说自己的想法（第一个停顿点） | 本技能 |
| 方案定稿后 | 用哪个视频模型、哪档清晰度（先看价目表和这条片子的合计价） | `$short-drama` |
| 分镜写完、项目里还没有图 | 图怎么来：用本机配好的出图、他自己出、还是不用图直接文生视频 | `$short-drama-storyboard` |
| 每张图、每段视频生成前 | 看预览和价格，确认才花钱（第二个停顿点，其实是很多次） | `$short-drama-produce` |
| 成片出来 | 对照检查的结果，哪里要重做（第三个停顿点） | 本技能 |

一张图一个确认，一段视频一个确认。方案定稿时数一遍「资产图几张 + 首帧几张 + 视频几段」，
把这个次数告诉他；一条 20 秒、4 个镜头的片子大约要点十几次。

## 1. 建项目

参考片第 1 步就下载，那时项目还没建：先定一个项目文件夹（名字用创作者的叫法，没有就取原片标题里的词），
在里面建 `项目开发/remake/R01/` 放参考片。方案定稿后，在**同一个文件夹**上按 `$short-drama` 的初始化做法建
单集项目（文件夹里已经有参考片目录不碍事）。首次 `init` 就带上从原片定下来的事实：画幅取原片画幅，
`--episode-count 1`，`--target-seconds` 取原片时长（四舍五入到整秒），说明语言用创作者说话的语言。
提示词语言他没有偏好就跟着视频模型走：先做第 3 节的第 1 步选好模型，用那个模型写法推荐的语言。

已有项目时，参考片目录照样放在 `项目开发/remake/` 下，新片作为新的一集。

## 2. 写节奏档案和语速

把复刻方案里的「节奏档案提议」交给 `$short-drama`，走它的创作者决策写入
`creator_authority.rhythm_profile`。**十个字段都要写**，少一个工具就拒收。数字从原片推出来，默认这样取：

| 字段 | 取值 |
|---|---|
| `form` | 按画风选 `ai_live_action` 或 `motion_comic` |
| `first_hook_seconds` | 原片第一个钩子的起点，向上取整，最少 1 |
| `beat_interval_seconds_max` | 原片相邻情绪点的最大间隔，向上取整 |
| `opposed_reversals_per_episode_min` | 原片里**有对手**的反转次数：有人在施压、另一个人顶回去或认输才算；东西自己坏了、环境变了不算。没有就写 0，不要为了凑这个数给新片加原片没有的对手戏 |
| `end_on_peak` | 原片在最后一个情绪点之后 1 秒内结束写 `true`；后面还留了一段余韵写 `false` |
| `reprise_previous_last_beat` | 单集复刻写 `false` |
| `vo_share_max` | 原片旁白占全部口播的比例，加 0.1 余量，最多 1。原片没人说话写 1，这一项就不起作用 |
| `target_avg_shot_seconds` | 原片平均镜长。它比所选视频模型一段的最长时长还长时，写拆开以后的平均段长（见第 3 节） |
| `close_shot_share_min` | 原片近景类镜头（近景、特写、大特写、细节镜头）占全片镜头数的比例，按拉片结果里填的景别数，向下取到 0.05；一个都没有写 0 |
| `first_major_payoff_by_episode` | 单集复刻写 1 |

语速 `format.pacing` 也在这一步定，同样走决策写入（`--field /format/pacing`），两个数都要给，不然写作阶段
估不出秒数：

- `spoken_characters_per_second`：取 `source.profile.json` 里的 `chars_per_second`；原片没人说话写 4（用不上）。
- `seconds_per_action_paragraph`：原片时长 ÷ 方案的段落数，保留一位小数。

这些是起点，创作者可以改。档案必须由他接受后才写入：第一个停顿点已经把这份提议（连同语速）讲给他听，
他选定方案就算接受；他另外改了数字的，照他的写。

画风是全片最要紧的统一设定时（例如「黑白监控画面」「手持纪实」），不要只写在方案里：交给 `$short-drama`
记成项目的视觉方向（`/creator_authority/visual_direction`，同样走决策写入）。《视觉设定.md》只收人物、造型、
地点、道具，装不下画风。

在 Git Bash 里，`--field /creator_authority/...` 会被改写成 Windows 路径而报错：命令前加
`MSYS_NO_PATHCONV=1`。PowerShell 里没有这个问题。

## 3. 依次交给各技能

每一步把下面这句请求连同复刻方案的路径交过去。对方技能照它自己的规矩做，遇到真正的创作分叉，
由它问创作者。顺序是穿插的：图要先出来、绑进分镜，视频提示词才写得了。

| 顺序 | 交给 | 请求要点 |
|---|---|---|
| 1 | `$short-drama`（选视频模型） | 给创作者看价目表和这条片子在各模型上的合计价（按方案的镜头时长估），他亲手选定模型和清晰度后写进生产档案。**排在最前面**：模型决定一段最长几秒、一段装得下几个动作、提示词用哪种语言，选晚了剧本和分镜都要返工 |
| 2 | `$short-drama-write` | 按复刻方案的逐镜对照写这一集的《剧本.md》：段落顺序和每段职责照方案，台词全部用方案里的新台词或在其基础上润色，不得出现原片原句。剧本里不写秒数，时长留给分镜对着方案排。旁白和口播照 [口播稿写法](voiceover-writing.md)；写完跑 `script_check.py check`，剧情类只看照搬和口气几项，没有台词的剧本不用跑 |
| 3 | `$short-drama-assets` | 按「全片统一设定」拆人物、造型、地点、道具 |
| 4 | `$short-drama-image-prompts` | 资产图提示词 |
| 5 | `$short-drama-produce`（出资产图） | 每张先给预览，创作者确认才生成；出完由分镜技能绑成参考图 |
| 6 | `$short-drama-storyboard` | 分镜按逐镜对照排，镜长贴着原片，关键镜头（钩子、转折、兑现）保留原片的时长比例。短于模型最短时长、长于模型一段上限的镜头，都照分镜技能的规矩处理；长镜头拆成了几段、多出几处接缝，回头写进方案 |
| 7 | `$short-drama-produce`（出首帧） | 每镜的首帧同样一张一确认；出完由分镜技能绑成起始帧 |
| 8 | `$short-drama-video-prompts` | 视频提示词。起始帧还没绑上时它不会写，这是它的规矩，不要绕过去 |
| 9 | `$short-drama-produce`（出视频） | 一段一确认。**每张图、每段视频都先看预览和价格，创作者确认才花钱**：这是第二个停顿点，由生产技能的确认闸门负责，本技能不代他确认 |
| 10 | `$short-drama-edit` | 剪辑单的切点和节奏对照原片；字幕取新剧本的台词。原片从头到尾有声音（`source.profile.json` 的 `continuous_bed` 是 `true`）而所选模型出的视频没有声音时，先让创作者从免费清单里挑一首配乐（做法见图文动效路线的「配乐」一节），再做成和成片一样长的垫底：`fetch_music.py fetch <编号> --out <项目>/制作/配乐 --length <成片秒数>`，片子里有人说话就再加 `--voice <人声文件>`。把 `配乐垫底.wav` 交给剪辑技能当环境声，从第一段铺到结尾 |

视频模型和分辨率只能由创作者亲手选，选之前先给他看价目表，做法见 `$short-drama-produce`。出图走 yoyo 中转，
每张 0.40 元：按方案算合计时给 `--estimate` 加上 `--draw <资产图加首帧的张数>`，图片就算在每个选项里了。

分镜或更后面的技能把方案里的镜头数、时长改了（比如一个长镜头拆成了三段），由本技能把 `复刻方案.md` 的
逐镜对照改成实际的样子，重新出一次网页预览，把改了什么告诉创作者。

## 4. 第三个停顿点：成片对照

成片出来后，按复刻尺度文档里的「成片对照检查」把新片和原片并排对一遍，结果写进复刻方案最后一节，
连同成片一起交给创作者。哪一项不通过，就只把那一镜交回负责的技能重做。
