# 拆解：这条为什么火

拆解的产物是 `拆解报告.md`，模板见 [报告模板](report-templates.md)。目标不是夸原片，而是给后面的复刻
一份**能照着做**的说明：哪几秒干了什么、靠什么留住人、哪些能学、哪些必须换。

## 一、事实和判断分开写

- **测到的**：时长、画幅、切点和镜长（拉片脚本量的）、台词时间（识别结果或画面字幕）、
  响度、停顿、画面最长不动、语速（`media_profile.py` 量的）、平台数据。只写来源能证明的东西。
- **看到的**：画面里有什么、字幕和花字写了什么、谁在做什么。写成可核对的句子，例如
  「0–1.2 秒：特写一只手把手机屏幕怼到镜头前，屏幕上是转账失败」，不写「开头很抓人」。
- **推测的**：为什么这样做、观众此刻在想什么。明确标「推测」，不和事实混写。
- 证据不够时直说「这段没看清 / 没有台词识别」，不编时间码，不补没看到的动作。

## 二、拉片：镜头是量出来的

用本技能自带的拉片工具（`vendor/video-shots/guide.md`）：切点、镜长、运动量由脚本实测，
景别、类别、运镜、画面和节奏角色由你看联系表填，最后过 15 道质量门。只有这几件事是你的活，
机器字段不要手改。

节奏角色按「观众这一刻得到什么」分成八种，每镜选一个，整片要么全标、要么全不标：
**钩子**、**铺垫**、**递进**、**重音**、**转折**、**兑现**、**换气**、**收口**。判据见
`vendor/video-shots/references/taxonomy.md` 第五节。复刻要整片标全，因为后面要拿它对照新片的节奏。

一张联系表只能看出「画面里有什么」，看不出「发生了什么」。关键镜头（钩子、转折、兑现）再抽
4 帧时间条看动作：

```bash
ffmpeg -v error -ss <起> -to <止> -i source.mp4 -vf "fps=4/<镜长>,scale=360:-1,tile=4x1" -frames:v 1 evidence/S03-strip.jpg
```

## 三、开头钩子：两条线一起看

前几秒决定观众留不留。钩子分两条线，缺一条就弱：

- **文案钩子**：反常识（打破认知）、痛点（直击难处）、数据（具体数字）、场景（还原生活画面）、
  悬念（话说一半）、利益（直接给好处）。写出原句（只做分析用，新片不用）、类型、和后文的关系。
- **画面钩子**：没见过的奇观、大量堆叠、画面突变或前后对比、夸张动作或表情、大字或红叉弹出、
  第一人称手持直给。写出具体画面：景别、色调、运镜、特效。
- **两条线配不配**：文案和画面是不是在同时强化同一件事。
- **首帧测试**：只看第 0 秒那一帧，单独截出来能不能让人停下。
- **前 3 秒的声音**：有没有音效、音乐突变、人声语气变化。
- **钩子强度**：1–10 分，附一句理由。这是给创作者看的判断，不是门槛。

## 四、结构和节奏：每段在干什么活

按节奏角色把镜头归成段，**用职责命名**，例如「0–3.1 秒 钩子：先给结果」「3.1–9.8 秒 铺垫：
交代谁、在哪、要干什么」，不用「开头」「中间」这种空名字。常见骨架只作参考：

- 钩子 → 痛点 → 方案 → 效果 → 引导行动（种草）
- 钩子 → 之前 → 过程 → 之后 → 引导行动（对比）
- 钩子 → 铺垫 → 递进 → 转折 → 兑现 → 收口（剧情）

同时记下这些可量的节奏数字，后面会写进新片的节奏档案：

| 数字 | 怎么来 |
|---|---|
| 平均镜长、每分钟切几次 | 拉片报告直接给 |
| 第一个钩子落在第几秒 | 第一个 `钩子` 角色镜头的起点 |
| 相邻两个情绪点最长隔几秒 | 相邻 `钩子 / 重音 / 转折 / 兑现` 镜头起点的最大间隔 |
| 每秒口播几个字 | 台词总字数 ÷ 有人声的总秒数 |
| 有没有连着六镜以上同一种角色 | 拉片脚本会提示；这里往往是观众划走的地方 |

## 五、画面和声音的「系统」

**声音你听不见，只能靠量。** `source.profile.json` 里的这几项照抄进报告，成片要拿它们对照：

| 数字 | 看什么 |
|---|---|
| `continuous_bed` 和每分钟停顿次数 | 几乎没有停顿，说明人声底下垫着配乐，新片也要垫 |
| `long_pauses` | 0.6 秒以上的空白有几处；原片没有，新片就不能有 |
| `integrated_lufs` | 原片多响；新片至少到 -15 LUFS |
| `longest_still_s`、`still_in_first_3s` | 原片画面最长多久不动、开头动没动；新片不能比它僵 |
| `chars_per_second` | 每秒说几个字，新稿的字数照它算（要先跑台词识别） |

人声是男是女、多大年纪、什么劲头，你判断不了，就写「待创作者确认」，到试听选声时让他用耳朵挑。
**口气**能从台词里读出来，要写清楚：是自信下判断，还是娓娓道来，是吐槽，还是煽情。新稿要学这个口气。

有些元素跨镜头一直在：固定的字幕样式和位置、反复出现的花字或贴纸、统一的色调、固定机位、
从头铺到尾的音乐。把它们当成一个系统写一次：长什么样、什么时候进、什么时候变、怎么退场。
音乐写情绪、节奏快慢和大概的 BPM，写清跟哪些切点对齐了。**不写歌名、不提取原曲**：
新片的音乐另外生成或另选。

## 六、三层拆开：能学的、必须换的、可以挑着学的

| 层 | 是什么 | 复刻时 |
|---|---|---|
| 结构动作 | 钩子的形状、段落顺序、转折位置、节奏数字、每镜的职责 | 学，这是它火的骨架 |
| 具体内容 | 原台词、原人物和长相、原品牌和账号、原画面、原配音和音乐、原作者的口头禅 | 必须换 |
| 呈现手艺 | 字幕样式、色调、运镜习惯、转场、音效用法 | 挑着学，不必全学 |

再单独列出**学不来的东西**：特定达人的个人魅力、品牌本身的势能、真实事件和现场、平台活动的流量
加成。这些不算进「为什么火」可以复制的部分，免得新片押错地方。

## 七、为什么火：三到五条

每条写成「做法 → 观众的反应 → 证据位置」，例如「第一句就是观众的原话『我账户里一股都没有，
可我每天打开盘面二十多次』→ 散户觉得说的是自己 → 0–3.5 秒，S01–S02」。每条都要指到具体的秒
和镜号，指不到的就不是证据，是感觉。

## 八、能仿几成

按你后面要用的生成方式，老实估计能做到多像：

- 剧情短片、空镜加旁白、文字和数据动效、产品展示：AI 生成能做到七八成。
- 真人对镜头说话、真人跳舞、真人现场反应：AI 做出来又贵又假，建议改成空镜加旁白、角色演绎或
  文字动效，并说明会损失什么。
- 依赖真实场景或真人身份的（探店、街采、名人）：只学结构，内容必须完全换成能生成的。

- K 线、图表、文字讲解这类图文动效：走 [图文动效路线](motion-graphics-route.md)，用代码在本机做动画，
  画面风格和节奏能做到八九成；声音靠试听选声，最像的是同类型，做不到原声。

把这个估计写进报告。第一个停顿点要让创作者在知道它的前提下做选择。

## 九、走哪条路线

| 原片画面 | 路线 |
|---|---|
| 有人、有实景、有商品 | 剧情和实拍类：照 [交接](handoff.md) 交给出片流程 |
| 没有人，主体是 K 线、图表、数据、文字、图标在动 | 图文动效类：照 [图文动效路线](motion-graphics-route.md) 做 |
| 两种都有（比如真人讲解加图表） | 人物部分走出片流程，图表部分用 HyperFrames 做成叠层，在报告里写清哪段归哪边 |

写进报告的「原片事实」，第一个停顿点讲给创作者听。
