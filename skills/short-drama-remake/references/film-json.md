# film.json：画面清单怎么写

图文动效的画面不用写代码。你只写一份 `制作/动画/film.json`：全片分成哪几个画面、每个画面是哪一种、
上面写什么字、每样东西在旁白说到哪几个字时出现。`animation.py build` 把它和 `时间表.json` 排成成片要用的时间，
写错的地方它会直接说出来。`setup` 放进动画目录的那份是示例，照着改。

写完照这个顺序查，前一步没过不要做后一步：

```bash
python3 <本技能目录>/scripts/animation.py build <项目>/制作/动画 --timetable <项目>/制作/时间表.json
python3 <本技能目录>/scripts/animation.py cues <项目>/制作/动画
python3 <本技能目录>/scripts/animation.py check <项目>/制作/动画
python3 <本技能目录>/scripts/animation.py snapshot <项目>/制作/动画
```

- `build`：排时间。会提醒哪一段旁白没有画面管、哪个画面开头是空的。
- `cues`：把全片列成一张对词清单，一行一样东西：第几秒出现、写的什么、那一刻旁白在说哪一句。**逐行读一遍**，
  画面上的字和旁白说的不是一回事，就改那一项的 `at`。这一步不出图，几秒钟，比看截图先做。
- `check`：检查字有没有叠在一起、出画。要 0 个错误。它只打印几行摘要。
- `snapshot`：每个画面开头截一张，每样东西出现后各截一张，汇总图在 `制作/动画/snapshots/`。想细看某几个时刻，
  加 `--at 12.5,30.2`，这一批存在 `snapshots-at/`，不会冲掉前面那批。

## 整体

```json
{
  "keywords": ["放量", "区间"],
  "palette": { "bg": "#050607", "up": "#ff3b3b", "down": "#2fe0d0", "key": "#ffd23f", "text": "#f5f7fa" },
  "scenes": [ { "type": "title", "segment": 1, "text": "放量了\n**为什么还跌**" } ]
}
```

- `scenes`：画面，按时间顺序写。前一个画面到后一个开始时自动退场。
- `keywords`：这些词在字幕里显示成重点色。字幕是 `build` 从时间表里取的，不用写。
- `palette`：底色 `bg`、涨 `up`、跌 `down`、重点色 `key`、文字 `text`。不写就是上面这一套。
  **这套模板只做深色底**：标注的底、字幕的描边都是按深色配的，`bg` 写成浅色 `build` 会拒绝。原片是浅色底时，
  学它的重点色和涨跌色，底色仍用深色。原片整个是另一种画风的，写 `style`（见下面「风格片」）。
- `style`：照 [风格库](styles.md) 的哪一种画，写编号，例如 `"12-aurora-glass"`。不写就是模板的黑底金字。
- 任何一处文字里，用两个星号包住的词显示成重点色；`\n` 换行。

## 一个画面管哪一段旁白

| 写法 | 意思 |
|---|---|
| `"segment": 2` | 管时间表里的第 2 段（从 1 数）。连着两段写 `[2, 3]` |
| `"from": "回落之后"` | 一段旁白要换几个画面时，后面的画面加这一项：旁白说到这几个字时换上来，句子中间也可以 |
| `"from": "s3"` | 从这一段的第 3 句开口时换上来 |
| `"seconds": 5` | 没有配音时用（示例、演示）：这个画面放 5 秒 |

每一段旁白都要有画面管。一段话换一两次画面，一个画面撑不过十几秒；同一种画面不要连用三次。
一个画面至少要留 0.8 秒：后一个画面的 `from` 紧贴着前一个的开头，`build` 会报出来。

## 东西什么时候出现：`at`

画面里每样会「出现」的东西（一行大字、一条要点、一根柱子、一条线、一个标注、一个结论章）都有 `at`。

| 写法 | 什么时候出现 |
|---|---|
| `"at": "回落幅度"` | **旁白说到这几个字的时候。首选这种写法**：从旁白稿里原样抄两到六个字 |
| `"at": "s2"` | 这个画面在场期间，第 2 句开口的时候 |
| `"at": 1.5` | 这个画面开始后 1.5 秒 |
| `"at": "40%"` | 这个画面的四成处 |
| 不写 | 各条自动落在各句开口的时候 |

- 抄的字要是**这个画面在场时**说的：从这个画面上场的那个字算起，到下一个画面上场为止。说得更早或更晚，
  `build` 会报出来，并把这个画面里说的话列给你。
- 卡片、柱子、大字在画面上的位置照你写的顺序排；先亮哪一个由 `at` 定，可以和排的顺序不一样。
- 同样几个字在这个画面里说了两遍，取第一遍；想要第二遍就多抄几个字。
- 用了 `from` 的画面，`"s1"` 是它自己上场以后开口的第一句，不是整段的第一句。
- K 线标注的 `at` 是标注**读得到**的时刻：镜头会提前 0.7 秒左右动身。所以照旁白说到它的那几个字写就行。

## 画面种类

### title：大标题

第一帧就有字，砸下来带闪光，字上再过一道高光。全片第一个画面用它。

```json
{ "type": "title", "segment": 1, "text": "放量了\n**为什么还跌**", "sub": "看清三件事再动手" }
```

一行五六个字以内字最大，再长会自动缩小。`sub` 可以不写。

### kline：K 线图

K 线一根根长出来；讲到哪根，镜头推近、其余变暗，套上光圈、打上大字标注；还能划线、划区间。

```json
{
  "type": "kline", "segment": 3, "header": "先看一个**走得顺**的例子",
  "shape": "breakout", "bars": 44, "seed": 12, "show": "key+2",
  "lines": [{ "price": "support", "to": "resistance", "at": "在区间里来回", "label": "原来的区间" }],
  "focus": [
    { "bar": "key", "at": "越过上沿", "note": "越过**上沿**", "until": "两件事同时" },
    { "bar": "key", "point": "volume", "at": "参与也增加", "note": "量也**放大**了" }
  ]
}
```

图从哪来，二选一：

| 字段 | 写法 |
|---|---|
| `shape` | 现成的走势：`breakout` 横盘后放量突破、站住；`fakeout` 突破后又跌回；`up` 一路涨；`down` 一路跌；`range` 横盘；`top` 涨一段后冲高回落（长上影）；`bottom` 跌一段后探底回升（长下影）。配 `bars`（多少根，默认 40）和 `seed`（换一个数就换一张图） |
| `data` | 自己编一组：每根写成 `[开, 高, 低, 收, 量]`，至少 5 根；再用 `key` 指明最要紧的是第几根（从 0 数）。不到十六根时每根保持正常粗细，整组居中 |

图表都是示意，不用真实股票的名字和代码。

「第几根」的写法（`bar`、`bars`、`show` 都认）：数字是从 0 数的序号；也可以不数，写 `"key"`（最要紧的那一根：
`shape` 里是放量的那根，约在全图三分之二处）、`"key+3"`（它后面第 3 根）、`"key-1"`、`"last"`（最后一根）、`"last-2"`、`"first"`。

| 字段 | 意思 |
|---|---|
| `header` | 画面左上角的小标题 |
| `show` | 只长到第几根为止（这一根也露出来），后面的先不露。例如 `"key+1"` |
| `continue` | `true`：接着前一个 K 线画面的那张图往下讲，已经在的不重新长，线也留着，只长新露出来的那几根，图的位置不变。用它做「一张图贯穿到底」：前一个画面 `show` 到一半，后一个 `continue`。全片第一张图不能写 |
| `lines` | 横线：`price` 写价格，或 `"resistance"`（关键那根之前的高点）、`"support"`（之前的低点）。再写 `to` 就是两条线夹出来的一个区间。`label` 是线上的字，不超过十个字 |
| `focus` | 聚焦，见下 |

聚焦的每一项：

| 字段 | 意思 |
|---|---|
| `bar` | 圈哪一根。不写就是 `"key"` |
| `bars` | 框住一段，写两头：`["key+1", "key+8"]`。讲「后面这一段」「回落的这几天」用它 |
| `point` | 光圈套在这根的哪头：`"high"`（默认）、`"low"`；`"volume"` 是框住这根的**量柱**，讲成交量时用 |
| `note` | 标注的大字。横屏放在光圈右边，每行不超过八个字，最多两行；竖屏放在图下面，每行不超过十个字 |
| `at` | 标注读得到的时刻 |
| `until` | 标注留到什么时候，要比 `at` 晚。不写就留到下一个聚焦之前，或者这个画面结束 |
| `zoom` | 推近的倍数。不写会自己算 |

- 一个聚焦从动身到看清要 2 秒左右，至少留 2 秒；一个画面两三个聚焦就够。聚焦排得太密，标注只闪一下。
- 图刚开始长的头一秒多排不了聚焦：第一个聚焦最早在画面开始后 1.2 秒左右。
- 镜头推近到 K 线时，量柱在画面下方甚至画外。旁白在讲量，就用 `"point": "volume"` 把镜头带到量柱上。

### compare：两张小图并排

横屏左右排，竖屏上下排。每边一张小 K 线图、一个结论章。

```json
{
  "type": "compare", "segment": 4, "from": "s5", "header": "量柱没变，**证据变了**",
  "left":  { "title": "回落后重新走高", "shape": "breakout", "seed": 21, "line": "resistance", "verdict": "走高", "good": true,  "at": "重新走高" },
  "right": { "title": "收回区间",       "shape": "fakeout",  "seed": 22, "line": "resistance", "verdict": "收回", "good": false, "at": "收回区间" }
}
```

每边：`title`（不超过十个字）、`shape` 或 `data`（同 K 线图）、`line`（在这张小图上划一条线，写法同横线的 `price`）、
`verdict`（结论章，两到三个字）、`good`（`true` 用涨的颜色，`false` 用跌的颜色）、`at`（章盖下来的时刻）。

### points：要点卡片

先出空位，讲到哪条亮哪条。三条以内竖着排，四条以上分两列（竖屏都是一列）。

```json
{ "type": "points", "segment": 6, "header": "看见放量，**问三句**",
  "items": [{ "title": "比近期**多了多少**", "at": "和近期相比" }, { "title": "前面是整理，还是**走远了**", "at": "前面是整理" }] }
```

每条 `title` 不超过十四个字；可加一行小字 `body`。最多六条；带小字的最多四条，再多小字会小到看不清。

### bars：柱状图

讲到哪根长哪根，可以点亮其中一根。竖屏是横条。

```json
{ "type": "bars", "segment": 2, "from": "再看高度", "header": "同样高的柱子，要看**放在哪**", "unit": "倍", "emphasize": "max",
  "items": [{ "label": "二十天平均", "value": 1, "at": "和最近二十天" }, { "label": "今天", "value": 3.2, "at": "今天这一根" }] }
```

`items` 每条写 `label`（不超过六个字）和 `value`（零以上的数）。柱子的长短按最大的那个数来比。`unit` 跟在数字后面；
`emphasize` 写第几根（照你写的顺序从 1 数）或 `"max"`（最大的那根）。

### number：一个大数字

数字像里程表一样滚出来。

```json
{ "type": "number", "segment": 2, "from": "s3", "header": "一笔成交怎么记", "value": 600, "suffix": "股",
  "label": "一个人买进，接住**三个人**卖出",
  "notes": [{ "text": "人数可以不同，**股数一样**", "at": "股数一样" }] }
```

`value` 是数字；`prefix`、`suffix` 跟在前后；`label` 是数字下面的一行；`notes` 是再往下的小字，最多三条。
`at` 是数字开始滚的时刻，不写就是画面一上来。

### statement：大字

一行一行蹦出来，适合一句结论、一句反问。

```json
{ "type": "statement", "segment": 7, "lines": [{ "text": "热闹，**不等于**确认", "at": "把热闹当成" }, { "text": "价格检验你的**理解**", "at": "后面的价格检验" }] }
```

一行不超过十四个字，最多四行。这种画面没有小标题，第一行出来之前屏上是空的：第一行的 `at` 要落在这个画面
开头一秒以内，做不到就把这个画面的 `from` 往后挪到说那句话的地方。`build` 会提醒。

### end：片尾

```json
{ "type": "end", "segment": 7, "from": "本片图表", "text": "图表仅作教学示意\n不构成投资建议", "badge": "AI 配音" }
```

### custom：自己写的画面

上面几种都不合适（流程图、地图、别的图表）才用。在 `制作/动画/custom.js` 里定义
`window.CustomScenes = { 名字: function (scene, ctx) { … } }`，在 `index.html` 里排在 `lib/kit.js` 前面引入，
`film.json` 里写 `{"type": "custom", "fn": "名字", "segment": 3}`。自己加的字段随便起名；画面的 `at`，以及任何一个
「每项是对象、其中有项写了 `at`」的列表，`build` 都会照上面的写法换成秒数。`ctx` 里有时间线 `ctx.tl`、这个画面的图层 `ctx.layer`、
画幅 `ctx.W` 和 `ctx.H`、建元素的 `ctx.el`，以及模板自己用的 `ctx.chart` 和 `ctx.keepAlive`。时间用 `scene.start`、
`scene.end` 和你在 `film.json` 里写的各个 `at`，到这里都已经是秒数。动画只动位置、缩放、旋转、透明度；要随机就用
`ctx.rng(种子)`。写法细节看 `animation.py tool <动画目录> -- docs gsap`。也可以直接改 `lib/kit.js`，那是这条片子
自己的一份；`setup` 不会覆盖它，加 `--force` 才换回模板。

`custom.js` 不用自己往 `index.html` 里加，`build` 会把它接在 `lib/kit.js` 前面；`film.json` 里有 custom 画面而
`custom.js` 不在、或者里面找不到某个 `fn` 的名字，`build` 会直接说。另外几样 custom 画面能用的：

| 写法 | 做什么 |
|---|---|
| `ctx.frames(scene, function (t, p) { … })` | 按时间画的东西（Canvas、WebGL、一直在变的 SVG 路径）：这个画面在场的每一帧都调一次，`t` 是画面开始后的秒数，`p` 是进度 0 到 1。只按 `t` 画，不用 `requestAnimationFrame`、时钟和 `Math.random`；WebGL 要开 `preserveDrawingBuffer: true` |
| `window.CustomBackdrop = function (ctx) { … }` | 全片共用的大背景（极光、纸纹、网格），整条片子一直在，不跟着画面淡入淡出。`ctx.layer` 是背景层，`ctx.total` 是全片秒数，配合 `ctx.frames({start: 0, end: ctx.total}, …)` 画 |
| 列表里某一项写 `"sound": "pop.mp3"` | 这一项出现时配一个音效，可加 `"volume": 0.4`（0.2 到 0.7，1 是和人声一样响）。能用的：`pop.mp3`、`click.mp3`、`click-soft.mp3`、`chime.mp3`、`ping.mp3`、`sparkle.mp3`、`notification.mp3`、`whoosh.mp3`、`whoosh-short.mp3`、`whoosh-cinematic.mp3`、`impact-bass-1.mp3`、`impact-bass-2.mp3`、`riser.mp3`、`typing.mp3`、`key-press.mp3`、`glitch-1.mp3`、`glitch-2.mp3`、`glitch-3.mp3` |
| 画面上写 `"transition": "fade"` | 这个画面怎么换上来：`slide`（模板的推入，默认）、`fade`（淡入淡出）、`cut`（硬切）。任何画面都能写 |

## 风格片

照 [风格库](styles.md) 的某一种画风做，`film.json` 这样写：

```json
{
  "style": "12-aurora-glass",
  "palette": { "bg": "#0a0820", "text": "#f3f1ff", "key": "#a8f0ff", "up": "#ff7a9c", "down": "#58e6c8" },
  "keywords": ["放量"],
  "scenes": [
    { "type": "custom", "fn": "hook", "segment": 1,
      "beats": [ { "what": "trap", "at": "下一根", "sound": "whoosh-short.mp3" } ] }
  ]
}
```

- 画面全部写 `custom`：写了 `style`，模板自带的那几种画面 `build` 会拒绝，它们是黑底金字那一套。
- `palette` 的 `bg` 写成这种风格的底色，浅色也可以：画面切换时露出来的就是它。底下那几条网格线不再画。
- 画面之间默认淡入淡出，某个画面要别的写 `transition`。
- 每个画面要出现的东西照常写成带 `at` 的列表（上面的 `beats`，名字随你起），时间由 `build` 排好，`custom.js`
  里按 `scene.beats` 取。
- 字幕仍由模板加，白字黑描边；要更轻的样子，在 `custom.js` 里改 `.mk-caption`，但这条片子的底上要一样看得清。

## 常见毛病怎么改

| 看到的 | 改法 |
|---|---|
| `cues` 里某一行，画面的字和旁白说的不是一回事 | 那一项的 `at` 改成旁白里真正说到它的那几个字 |
| `build` 说某个画面开头是空的 | 把这个画面的 `from` 往后挪，或者把第一样东西的 `at` 提前 |
| `build` 说某一段没有画面管 | 加一个画面管它，或者让前一个画面写成 `[2, 3]` 连着管 |
| `build` 说上次混的声音取下了 | 混音以后又改了画面的时间：重新运行 `mix_audio.py`，再 `build --mix` |
| 标注只闪了一下 | 这个画面聚焦太多或太密：删掉一个，或者拆成两个画面（后一个用 `continue`） |
| 旁白在讲成交量，画面上看不到量柱 | 那个聚焦加 `"point": "volume"` |
| 连着两个画面是同一张图，观众看到它长了两遍 | 后一个画面加 `"continue": true` |
| 线上的字压住了 K 线 | 字会自己躲到蜡烛少的一头；还压就把字缩短，或者挪进 `header` |
| 截图里字挤在一起、出画 | 字太长：照上面各种画面写的字数缩短 |
