# Agent Note: 首帧任务的持久化来源校验

Status: implemented

## Problem

从规范分镜的 SHOT 条目准备图片任务时，预览按源文档映射接受该条目；后续确认、执行和状态读取仍按模态硬编码图片只接受 IMG 前缀，导致已准备的合法首帧任务无法继续。现有首帧测试只覆盖预览和错误输入，没有验证完整生产生命周期。

## Decision

持久化任务读取与准备阶段使用同一份源文档前缀映射。补齐使用离线 fixture adapter 的首帧预览、确认、执行与状态测试，并回归精确确认、来源漂移和篡改拒绝行为。

## Alternatives considered

将首帧复制到图片提示词文档可以复用现有 IMG 路径，但会制造第二份创作来源并掩盖已承诺的 SHOT 入口缺陷，因此不用。删除前缀检查可以让合法任务继续，但也会放行不匹配的源条目，因此不用。

## Consequences

合法分镜首帧可以沿既有确认流程生产。来源文件、条目、输入指纹、一次性确认与输出约束仍须共同满足；不改变任务格式、付费参数或模型选择。

## Validation

新增首帧生命周期回归先在旧代码下复现错误，再在修复后通过。Python 3.10 的生产模块执行 34 个测试，无失败，符号链接权限相关子用例跳过 3 项。ruff 0.15.11 全库检查通过，git diff --check 通过。

Python 3.10 全量执行 765 个测试，结果为 5 个 failure、2 个 error、19 个 skip。对修改前提交 3778b44480e6 的源码快照复跑对应 6 个测试方法，重现相同的 7 条失败：浏览器光标与复制队列、Windows 目录描述符和符号链接、保留文件名以及两份旧评估文档的加粗格式。

Python 3.9.25 全量执行 765 个测试，结果为 6 个 failure、46 个 error、37 个 skip；原始源码快照也执行 765 个测试，结果为 7 个 failure、47 个 error、40 个 skip。当前版本的全部失败条目均在原始源码快照中出现，基线另有两条失败，不将其计为本次修复收益。主要兼容阻塞是原有 Path.stat(follow_symlinks=False) 在 Python 3.9 不可用，未在本次局部修复中扩展处理。

本次验证不代表全库测试通过，也不代表 Python 3.9 的完整生产链可用；实际生产继续使用本机 Python 3.10。
