# Agent Note: 本机配好内置出图时默认提议用 gpt-image-2 出图

Status: implemented

## Problem

一位创作者在 Codex 里说「按这个流程来」，技能写完五份文档后回报「你先按图片提示词制作三张图，再按分镜制作视频首帧；
视频模型待选定后再适配」，就停了。他本机已经配好 `~/.drama-skills/adapters.json` 和画图 Key，期望的是技能直接用
gpt-image-2 出图给他看，再选视频模型。

原因在路由文字：缺图时的「三条路」把「用本套件出图」写成「只是第一条路的一种做法，需要项目外的 adapter 与凭据」，
各阶段又都写「生产只有用户点名时开始」，没有一处让 agent 先看本机是否已经配好；选视频模型的价目表只在创作者
主动问时才给。

另有一个脚本缺口：分镜里先绑了资产图、首帧仍待补时，「输入参考图」写成 `REF-...；待补参考图：本镜起始帧`，
从这一镜 `SHOT-*` 准备首帧 job 会报「input-reference declaration is invalid」，先出资产图再出首帧的顺序走不通。

## Decision

- `$short-drama` 新增第 9 条：写完图片提示词或冻结关键帧而项目缺图时，运行 `provider_adapters.py --check-config`；
  显示画图 Key 已配置、adapter 配置已生成，就默认提议转 `$short-drama-produce` 用 `gpt-image-2` 出图。创作者说过
  「按流程来」「出图」「生成预览图」这类话就算点名，直接 `prepare` 展示预览；否则作为推荐下一步问他。
  `run` 仍要创作者看过预览后的本次明确确认，硬闸门不变。
- 第 7 条和分镜、视频提示词的「三条路」保留三条，本机配好时把 gpt-image-2 出图列为第一条路的推荐做法。
- 第 8 条：流程走到要用目标模型而档案仍是 `unset` 时，主动运行 `--price-table` 请创作者选；只列价格。
- 图片提示词、分镜的完成回报把「用 `$short-drama-produce` 出图」列为推荐下一步。
- `$short-drama-produce` 新增「出参考图和首帧」一节，写清 job 形状、尺寸约束和出图后绑 `REF-...` 的顺序。
- `production_tool.py`：从《分镜.md》画本镜首帧时，忽略真实 `REF-...` 之后的「；待补参考图：……」，与已有的
  `PLAN-...` 豁免一致；其他 job 仍拒绝待补。

## Alternatives considered

- 维持原文，只在 README 里教创作者说「用 `$short-drama-produce` 出图」。最强理由是改动为零、不碰路由；
  不用是因为创作者已经说了「按流程来」，期望技能自己走到出图，靠创作者记口令不可靠。
- 配好后直接 `run`。最强理由是少一次来回；不用是因为每次花钱都必须先给预览、等本次确认，这道闸门不能放宽。
- 让 `prepare` 对所有 job 忽略待补。最强理由是一处改动更简单；不用是因为视频 job 带待补就是没准备好，
  只有画首帧这个 job 本身就是在补缺口。

## Consequences

- 已配好的创作者写完提示词就能看到出图预览，不用再自己去别处做；没配好时行为与以前相同，并多一句如何配置。
- 回报里多一次 `--check-config`（离线，只显示有没有配置，不显示 Key）。
- 「按流程来」被当作点名出图，会多出一份预览；不确认就不花钱。
