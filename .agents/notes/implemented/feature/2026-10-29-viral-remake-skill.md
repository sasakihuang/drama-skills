# Agent Note: 新增爆款复刻技能 short-drama-remake

Status: implemented

## Problem

这个分支的用途变了：维护者要把它交给一位用 Codex 的朋友，让他丢一条抖音、快手或小红书视频的分享链接，
就能拆清楚这条为什么火，再照同样的结构做一条内容全新的视频。原套件从点子或原著出发，没有「从一条参考片
出发」的入口：不会取参考片，不会量镜头，也没有一份可以交给剧本和分镜的复刻方案。

## Decision

- 新增 `skills/short-drama-remake`，只负责参考片目录 `项目开发/remake/<R编号>/` 里的三样东西：原片和
  事实表、拉片结果、《拆解报告.md》与《复刻方案.md》。剧本、资产、提示词、分镜、生产、剪辑仍由原来的
  技能负责，本技能按技能名交接，不越过所有权。
- 取参考片用 `scripts/fetch_reference.py`，只用标准库。快手和小红书的 App 分享链接按手机方式打开，分享页里
  已带视频地址，不登录、不要 cookie。抖音的分享页不带数据，脚本返回 `need_browser`，由 agent 用它自己的
  浏览器在作品页里请求作品详情（页面安全组件只给 `XMLHttpRequest` 签名），存成 JSON 再交给 `douyin-detail`。
  三条路都不通时请创作者在 App 里保存视频，用 `local` 收进来。它是继生产 adapter 之后第二个允许联网的脚本，
  `tests/test_shipping_boundaries.py` 明确登记了它和它读的三个地址。
- 拉片随技能附带 eternityspring/reelbench-skills 的 `video-shots`（Apache-2.0，提交 df39d5d），放在
  `vendor/video-shots/`，原 `SKILL.md` 改名 `guide.md` 并去掉元数据，免得被安装工具当成独立技能。
  切点、镜长、运动量由脚本实测，模型只填景别、类别、运镜、画面和节奏角色。
- 识别台词可选：`scripts/transcribe.py` 在本机用 faster-whisper（CPU INT8），没装就改读画面字幕。
- 复刻尺度只给「中度」「大胆」两档；三处停顿：拆解后（照推荐、换题材或尺度、说自己的想法反复改）、
  生产报价、成片与原片对照。节奏档案从原片测到的数字提出，创作者在第一处停顿选定方案即接受。
- Dashboard 把 `short-drama-remake` 和 `项目开发/remake/` 归入分析栏，栏名改为「原著与爆款拆解」。

## Alternatives considered

- **整套换成 Hypit 一类的复刻工具**：它的复刻流程最完整，但要付费托管服务，许可证也不允许转给别人用。
- **用 yt-dlp 或现成的下载器**：覆盖平台最多，但 2026-10 实测抖音要「新鲜 cookie」，读浏览器 cookie 在
  Windows 上常失败；两款常用的下载器也走电脑网页版，不登录拿不到快手、小红书的作品数据。手机分享页加
  agent 自带浏览器不需要任何凭据。
- **保留「保守 / 原样复刻」一档**：最贴近原片，但台词近乎照抄、画面重画，侵权风险和平台搬运判定都落在
  创作者身上，所以不提供。
- **整段视频交给多模态模型看**：能同时听声音、看动作，但要另配 Key，结果也不可核对；实测切点加联系表
  加时间条，每条判断都能回到画面上对账。

## Consequences

- 收益：一条链接就能走完下载到成片的全流程，拆解有实测数字和证据位置，新片的节奏档案直接从原片来。
- 代价：平台改页面结构时取参考片会失效，要跟着改 `fetch_reference.py`；抖音那一步依赖 agent 的浏览器
  能在页面里执行脚本。拉片工具要 `node`。附带的第三方代码要按 `vendor/video-shots/ATTRIBUTION.md`
  整目录更新。小红书视频的取法还没用真视频验证过。
